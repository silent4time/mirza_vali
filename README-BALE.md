# راهنمای افزودن پشتیبانی بله به میرزا بات (Mirza Bot)

این راهنما توضیح می‌دهد چه چیزی تغییر کرده، چرا این‌طور طراحی شده، و برای فعال‌سازی چه کارهایی باید انجام دهید.

## خلاصه‌ی معماری فعلی ربات (قبل از پچ)
میرزا بات یک پروژه‌ی PHP نسبتاً بزرگ است (بیش از ۹۰ فایل، حدود ۱۷۴۵ فراخوانی `sendmessage()`). نکات کلیدی که تحلیل کد نشان داد:

- تمام ارتباط با API از یک تابع واحد در `botapi.php` به نام `telegram()` عبور می‌کند و آدرس `api.telegram.org` و توکن، **درون همان تابع هاردکد شده بود**.
- ورودی وبهوک هم در همان فایل پردازش می‌شود: از بدنه‌ی JSON دریافتی، متغیرهایی مثل `$from_id`, `$chat_id`, `$text` و... استخراج می‌شوند و در ادامه‌ی کل پروژه (index.php، admin.php، api/*.php و...) استفاده می‌شوند.
- شناسه‌ی کاربر (`id`) در جدول `user` و جداول مرتبط (invoice، Payment_report و...) از نوع `VARCHAR` است، نه عدد صحیح با محدودیت خاص — این نکته مهمی بود که اجازه داد راه‌حل کم‌تهاجمی طراحی شود (پایین‌تر توضیح داده شده).
- یک تابع `checktelegramip()` وجود دارد که فقط IP رنج رسمی تلگرام را قبول می‌کند؛ بله را پوشش نمی‌دهد.
- بخش «ایجنت / زیرربات‌های فروشندگان همکار» (`vpnbot/`, `mirza_agent.php`, بخش‌هایی از `admin.php`) یک زیرسیستم کاملاً مجزاست که هر همکار می‌تواند ربات تلگرامیِ اختصاصی خودش را بسازد. **این پچ آن زیرسیستم را پوشش نمی‌دهد** (توضیح در بخش محدودیت‌ها).

## طراحی راه‌حل
به‌جای بازنویسی ۱۷۴۵ محل فراخوانی، تغییرات را در پایین‌ترین لایه (`botapi.php`) و نقطه‌ی ورودی وبهوک اعمال کردیم تا کل بدنه‌ی کد بدون تغییر کار کند:

1. **تشخیص پلتفرم هر درخواست وبهوک** از روی URL:
   - آدرس تلگرام (بدون تغییر، سازگار با نصب‌های قبلی): `https://yourdomain.com/index.php`
   - آدرس بله: `https://yourdomain.com/index.php?platform=bale`
2. **جدا نگه‌داشتن شناسه‌ی کاربران بله از تلگرام** در همان دیتابیس مشترک: چون ستون `id` رشته‌ای (VARCHAR) است، شناسه‌ی عددیِ کاربر بله هنگام ورود، با یک عدد ثابت بزرگ (`BALE_ID_OFFSET = 9,000,000,000,000`) جمع می‌شود و همین مقدار در کل دیتابیس/کد ذخیره و استفاده می‌شود. هنگام ارسال واقعیِ پیام، تابع `telegram()` خودش آفست را کم کرده و آدرس/توکن درست بله را صدا می‌زند. **نتیجه:** نیازی به تغییر ۹۰+ فایل دیگر نبود، چون همه‌جا فقط با همین مقدار رشته‌ای کار می‌کنند.
3. **کرون‌جاب‌ها** (یادآوری انقضا، بک‌آپ و...) هم بدون تغییر کار می‌کنند، چون تشخیص پلتفرم بر مبنای خودِ `chat_id` ذخیره‌شده در دیتابیس انجام می‌شود، نه بر مبنای درخواست HTTP جاری.
4. جایگزینیِ `checktelegramip()` با `checkWebhookAuthorized()` که هدر `secret_token` (که خودتان هنگام `setWebhook` تعیین می‌کنید) را چک می‌کند — چون بله فهرست IP رسمی مثل تلگرام منتشر نکرده و تکیه به IP برایش ممکن نیست.

## فایل‌های تغییر یافته
پیوست شده‌اند (و `mirzabot-bale-support.patch` شامل diff کامل است):
- `config.php` — تنظیمات جدید (توکن‌ها، فلگ‌های فعال‌سازی، secret token، آفست)
- `botapi.php` — لایه‌ی مسیریابیِ پلتفرم
- `function.php` — تابع `checkWebhookAuthorized()`
- `index.php` — یک خط (فراخوانی تابع جدید به‌جای `checktelegramip()`)
- `admin.php` — یک خط (دانلود فایل تصویر بک‌گراند QR، پلتفرم-آگاه شد)

## مراحل فعال‌سازی

### ۱) تنظیم `config.php`
```php
$ENABLE_TELEGRAM = true;   // یا false اگر فقط بله می‌خواهید
$ENABLE_BALE     = true;   // یا false اگر فقط تلگرام می‌خواهید

$APIKEY          = 'توکن-ربات-تلگرام';   // مثل قبل
$BALE_APIKEY     = 'توکن-ربات-بله';      // از my.bale.ai

$WEBHOOK_SECRET_TOKEN = 'یک-رشته-تصادفی-و-طولانی-انتخاب-کنید';
```

### ۲) ثبت وبهوک هر پلتفرم
```bash
# تلگرام (بدون تغییر نسبت به قبل، فقط secret_token اضافه شده)
curl -F "url=https://yourdomain.com/index.php" \
     -F "secret_token=همان-مقدار-WEBHOOK_SECRET_TOKEN" \
     https://api.telegram.org/bot<TELEGRAM_TOKEN>/setWebhook

# بله
curl -F "url=https://yourdomain.com/index.php?platform=bale" \
     -F "secret_token=همان-مقدار-WEBHOOK_SECRET_TOKEN" \
     https://tapi.bale.ai/bot<BALE_TOKEN>/setWebhook
```
> نکته: پارامتر `secret_token` در setWebhook باعث می‌شود پلتفرم آن را در هدر هر درخواستِ وبهوک ارسال کند؛ `checkWebhookAuthorized()` همان هدر را تأیید می‌کند.

### ۳) تست
- یک پیام به ربات تلگرام بدهید → باید طبق روال قبلی جواب بدهد.
- یک پیام به ربات بله بدهید → باید (با شناسه‌ی داخلیِ آفست‌دار) به‌عنوان کاربر جدید در جدول `user` ثبت و پاسخ داده شود.
- در دیتابیس بررسی کنید ستون `id` برای کاربر بله یک عدد ~۱۳ رقمی (شروع‌شونده با آفست) است، نه همان شناسه‌ی خام بله.

## محدودیت‌ها و نکاتی که باید بدانید (صادقانه و مهم)

1. **زیرسیستم ایجنت/زیرربات (`vpnbot/`, `mirza_agent.php`)** — جایی که همکاران فروش می‌توانند ربات تلگرامیِ اختصاصی خودشان را از داخل ربات اصلی بسازند — همچنان فقط تلگرام را پشتیبانی می‌کند. افزودن بله به آن بخش، یک پروژه‌ی جداگانه و به همان اندازه بزرگ است (نیاز به فرم دریافت توکن بله در پنل ایجنت، تغییر ساختار ثبت وبهوک هر زیرربات و...).
2. **inline query** (جست‌وجوی این‌لاین) در بله پشتیبانی نمی‌شود؛ اگر جایی از این قابلیت در متن‌های ربات استفاده شده، برای کاربران بله غیرفعال می‌ماند (کد این را به‌صورت خودکار نادیده می‌گیرد، خطا نمی‌دهد).
3. **آفست عددی به‌جای تغییر اسکیمای دیتابیس**: این روش عمداً کم‌تهاجمی انتخاب شد تا داده‌های کاربران فعلیِ تلگرامِ شما دست‌نخورده بماند. جایگزینِ «درست‌تر» از نظر مهندسی، افزودن ستون `platform` و کلید ترکیبی به تمام جداول مرتبط با کاربر است، اما این کار چند ده فایل دیگر (`admin.php`, `panel/*.php`, `api/*.php`) را هم درگیر می‌کند و عملاً بازنویسیِ بخش بزرگی از پروژه است. عدد آفست (۹×۱۰¹²) به‌قدری بزرگ انتخاب شده که با فاصله‌ی زیادی از شناسه‌های فعلی تلگرام (که هنوز به مرز چند میلیارد نرسیده) فاصله دارد، اما **این یک تضمین ریاضی قطعی نیست**، صرفاً یک حاشیه‌ی امنِ بسیار بزرگ است.
4. **مسیر دانلود فایل بله** (`https://tapi.bale.ai/file/bot<token>/<path>`) بر اساس الگوی مشابه تلگرام حدس زده شده؛ پیش از اتکا در پروداکشن، آن را با مستندات رسمی `dev.bale.ai` تطبیق دهید.
5. این پچ روی نسخه‌ی فعلیِ ریپازیتوری (`main`, آخرین ریلیز 0.2.5) اعمال و از نظر **سینتکس PHP** با `php -l` تست شده است؛ اما چون به توکن واقعیِ بله یا سرور زنده دسترسی نداشتم، **تست عملکردیِ end-to-end روی سرور واقعی توسط شما لازم است** — پیشنهاد می‌کنم ابتدا روی یک نسخه‌ی تست (staging) با یک ربات بله‌ی آزمایشی امتحان کنید.

## نکته‌ی مهم که با تستِ روی سرورِ واقعی کشف شد (به‌روزرسانی)
اولین نسخه‌ی این پچ فرض می‌کرد بله هم مثلِ تلگرام هدرِ `X-Telegram-Bot-Api-Secret-Token` رو موقعِ تحویلِ وبهوک ارسال می‌کنه. تستِ زنده روی یک VM واقعی نشون داد **این فرض غلط بود** — بله این هدر رو اصلاً نمی‌فرسته، و در نتیجه هر پیامِ واقعیِ بله با «Unauthorized access» رد می‌شد (بدون هیچ خطای PHP، چون `die()` خطا نیست).

**راه‌حل:** رمزِ محرمانه، علاوه بر هدر، از طریق **پارامترِ URL** هم پذیرفته می‌شه (`function.php` و فایل‌های به‌روز شده‌ی پیوست این تغییر رو دارن). برای همین موقعِ ثبتِ وبهوکِ بله، باید حتماً رمز رو توی خودِ آدرس بذاری:

```bash
curl -F "url=https://YOURDOMAIN/index.php?platform=bale&secret=YOUR_SECRET" \
     "https://tapi.bale.ai/bot<BALE_TOKEN>/setWebhook"
```

⚠️ نکته‌ی فنیِ کوچیک: اگه از `curl -F` استفاده می‌کنی، مقدارِ `&` رو مستقیم و بدون انکود (`%26`) بذار — چون `curl -F` خودش این مقدار رو دقیقاً همون‌طوری که هست می‌فرسته، نیازی به انکودِ دستی نیست (اگه `%26` بذاری، بله کل رشته رو به‌عنوان یک پارامترِ واحد ذخیره می‌کنه، نه دو پارامترِ جدا).

وبهوکِ تلگرام همچنان می‌تونه از طریقِ هدر (روشِ قبلی) کار کنه، ولی برای یکدستی می‌تونی همون روشِ URL رو برای هر دو پلتفرم استفاده کنی.

## قابلیتِ جدید: پرداخت با کیفِ‌پولِ بله
میرزا بات از قبل زیرساختی برای پرداختِ داخلِ چت (طراحی‌شده برای Telegram Stars) داشت که هیچ‌وقت برای بله فعال نشده بود. این پچ همان زیرساخت را برای بله هم فعال می‌کند:

- طبقِ مستنداتِ بله (`docs.bale.ai`)، بازوها می‌توانند از طریقِ متدِ `sendInvoice` یک «درخواستِ پول» به کاربر بفرستند؛ کاربر آن را از کیفِ‌پولِ بله‌اش پرداخت می‌کند و پیامی حاویِ `successful_payment` برای ربات می‌رسد.
- برای فعال‌سازی، مقدارِ `$BALE_PROVIDER_TOKEN` را در `config.php` با شماره‌کارتِ بانکیِ متصل به حساب کسب‌وکارتان در بله پر کنید، و در پنلِ ادمین (یا مستقیم در دیتابیس، فعلاً)، مقدارِ `balepaystatus` در جدولِ `PaySetting` را از `offbalepay` به `onbalepay` تغییر دهید:
  ```sql
  UPDATE PaySetting SET ValuePay='onbalepay' WHERE NamePay='balepaystatus';
  ```
- دکمه‌ی «پرداخت با کیف‌پول بله» فقط برای کاربرانی که از طریقِ بله وارد شده‌اند نمایش داده می‌شود.

⚠️ **قبل از استفاده‌ی واقعی حتماً با یک تراکنشِ آزمایشیِ کوچک تست کنید** — مستنداتِ بله دقیقاً مشخص نکرده‌اند که مقدارِ `amount` در `sendInvoice` همان مبلغِ خامِ ریالی است یا ضرب‌شده در واحدِ کوچک‌تر (مشابهِ تلگرام). این جزئیات را با یک تراکنشِ کم‌مبلغ تأیید کنید تا از پرداختِ اشتباه (مثلاً ۱۰۰ برابر) جلوگیری شود.

## راه‌اندازیِ گروهِ گزارشات (مرحله‌ی الزامیِ بعد از نصب)
بعد از نصب و اولین اجرای موفقِ ربات، برای اینکه گزارش‌های ربات (فروش، پرداخت، خطاها و...) به‌صورت دسته‌بندی‌شده به یک گروه ارسال بشن، این گروه رو باید یک‌بار بسازی و به ربات معرفی کنی.

### ۱) ساختِ گروه در تلگرام
یک گروهِ **جدید** بساز، با این ویژگی‌ها:
- **نوعِ گروه:** خصوصی (Private)
- **حالتِ انجمن/تاپیک (Topics):** فعال — از تنظیماتِ گروه روشنش کن
- **دسترسی‌های لازم برای ربات (وقتی ادمینش می‌کنی):** تغییرِ اطلاعاتِ چت، پین‌کردنِ پیام، اضافه‌کردنِ یوزر، ارسالِ مدیا، ارسالِ پیام

### ۲) گرفتنِ آیدیِ عددیِ گروه
1. ربات `@myidbot` رو به همون گروه اضافه/عضو کن
2. داخلِ گروه دستورِ زیر رو بفرست:
   ```
   /getgroupid@myidbot
   ```
3. آیدیِ عددیِ گروه رو که برات می‌فرسته، جایی یادداشت کن

### ۳) ادمین‌کردنِ خودِ ربات
ربات میرزا بات (همون ربات تلگرامیت) رو هم به همین گروه اضافه و **ادمینِ گروه** کن.

### ۴) معرفیِ گروه به ربات
1. توی چتِ خصوصیِ ربات، به صفحه‌ای برو که کیبورد داره
2. دکمه‌ی **«گزارشات ربات»** رو پیدا و روش کلیک کن
3. یه پیام میاد که آیدیِ عددیِ فعلیت رو نشون می‌ده و می‌خواد آیدیِ گروه رو بفرستی:
   > 📣 در این بخش می‌توانید آیدی عددی گروه را برای ارسال اعلان ارسال نمایید
4. همون آیدیِ عددیِ گروه (از مرحله‌ی ۲) رو برای ربات بفرست

⚠️ **این مرحله الزامیه** — بدونِ تنظیمِ این گروه، بخشی از قابلیت‌های گزارش‌گیریِ ربات کار نمی‌کنه.

## قابلیت‌های جدید (دور اخیر)

**حذفِ خودکارِ HTML برای بله:** چون بله (برخلافِ تلگرام) هیچ فرمت‌بندیِ HTML رو تفسیر نمی‌کنه، از این به بعد پیام‌هایی که به بله می‌رن خودکار تمیز می‌شن (تگ‌ها حذف، لینک‌ها به فرمِ «متن (آدرس)» تبدیل می‌شن). برای تلگرام هیچ تغییری نکرده.

**همسان‌سازیِ گزارش‌ها بینِ دو ربات:** درخواست‌های خرید و اسکرین‌شاتِ تراکنش که به گروهِ گزارشاتِ تلگرام می‌رن، عیناً برای بله هم فرستاده می‌شن:
- اگه `$BALE_REPORT_GROUP_ID` رو پر کنی → به یه گروهِ معمولیِ بله می‌رن (آیدیِ گروه رو با ربات `@showchatdbot` بگیر، نیازی به تاپیک/انجمن نیست)
- اگه خالی بمونه ولی `$BALE_ADMIN_ID` پر باشه → به چتِ خصوصیِ ادمین می‌رن

⚠️ **ریسکِ بررسی‌نشده:** چون ادمین حالا می‌تونه از هر دو پلتفرم پرداخت رو تأیید کنه، مطمئن نیستم کد جلوی تأییدِ دوباره‌ی یه تراکنش (یه‌بار از هر پلتفرم) رو می‌گیره یا نه. فعلاً هر تراکنش رو فقط از یه پلتفرم تأیید کن.

**بله‌پی در پنلِ مدیریت:** یه ردیفِ کاملِ جدید (مثلِ زرین‌پال) به بخشِ مالیِ پنلِ ادمین اضافه شد: روشن/خاموش، تنظیماتِ توکنِ پرداخت، کش‌بک، حداقل/حداکثرِ مبلغ. همچنین یه بخشِ جدید («🤖 تنظیماتِ ربات بله») که ازش می‌تونی توکنِ ربات، آیدیِ ادمین، و آیدیِ گروهِ گزارشات رو **مستقیم از داخلِ چتِ تلگرام** ویرایش کنی — بدونِ نیاز به نصبِ دوباره یا دسترسی به سرور. این مقادیر روی `config.php` اولویت دارن.

## اگر بخواهید فقط یکی از دو پلتفرم فعال باشد
کافی است در `config.php` مقدار `$ENABLE_TELEGRAM` یا `$ENABLE_BALE` را `false` کنید؛ وبهوکِ پلتفرم غیرفعال هم اگر صدا زده شود، با کد ۴۰۳ رد می‌شود.

## تبدیل به اسکریپت نصب/آپدیت (`apply-bale-patch.sh`)
به‌جای کپی دستیِ فایل‌ها، یک اسکریپت `bash` هم آماده شده که خودش:
1. از فایل‌های فعلی سرور شما بک‌آپِ تاریخ‌دار می‌گیرد.
2. فایل‌های منطقیِ پچ‌شده (`botapi.php`, `function.php`, `index.php`, `admin.php`) را جایگزین می‌کند.
3. **کاری با `config.php` فعلیِ شما که توکن/دیتابیس واقعی توش هست نمی‌کند** — فقط اگر بلوک تنظیمات چندپلتفرمی از قبل توش نباشد، آن را به انتهای فایل اضافه می‌کند (مگر اینکه `--force-config` بدهید).

```bash
chmod +x apply-bale-patch.sh
./apply-bale-patch.sh /path/to/mirzabot
```

بعد از اجرا، فقط لازم است مقادیر `{BALE_API_KEY}` و `{WEBHOOK_SECRET_TOKEN}` را در `config.php` واقعیِ سرورتان جایگزین کنید و `$ENABLE_BALE` را `true` کنید.

## تست کامل، بدون سرور واقعی و بدون توکن واقعی (`run-local-test.sh`)
این اسکریپت روی همین کد، یک محیط کاملاً محلی می‌سازد و ثابت می‌کند مسیریابیِ تلگرام/بله و جداسازیِ شناسه‌ی کاربران درست کار می‌کند — **بدون اینکه به اینترنت یا توکن واقعی نیاز داشته باشد**:

- یک دیتابیس MariaDB محلی می‌سازد و اسکیمای واقعی پروژه را با همان `table.php` خودِ ربات ایجاد می‌کند.
- به‌جای `api.telegram.org` و `tapi.bale.ai`، یک «سرور جعلیِ API» محلی راه می‌اندازد که فقط هر درخواست را لاگ می‌کند و `{"ok":true}` برمی‌گرداند — یعنی می‌بینید *دقیقاً* به کدام آدرس/توکن زده شده، بدون نیاز به بات واقعی.
- خودِ ربات را با سرور توکاره‌ی PHP (`php -S`) بالا می‌آورد.
- یک پیام جعلیِ تلگرام و یک پیام جعلیِ بله (هر دو با همان شناسه‌ی عددیِ کاربر) به وبهوک می‌فرستد.

پیش‌نیاز (روی Ubuntu/Debian):
```bash
sudo apt-get install -y php-cli php-mysql php-curl php-mbstring php-gd php-xml mariadb-server
```

اجرا:
```bash
chmod +x run-local-test.sh
./run-local-test.sh /path/to/mirzabot   # پوشه‌ی حاوی نسخه‌ی پچ‌شده
```

### خروجی واقعی این تست (روی محیط من اجرا و تایید شد)
```
===== به کدام آدرس/توکن واقعا زده شد =====
11:43:13 POST /telegram/botTEST_TELEGRAM_TOKEN/sendmessage
11:43:13 POST /bale/botTEST_BALE_TOKEN/sendmessage

===== محتوای جدول user =====
id              username
111111111       tg_user
9000111111111   bale_user
```
یعنی:
- پیام تلگرام دقیقاً با توکن تلگرام به مسیر تلگرام رفت؛ پیام بله دقیقاً با توکن بله به مسیر بله رفت — با اینکه هر دو از یک شناسه‌ی عددیِ یکسان (`111111111`) به‌عنوان ورودی استفاده کردند.
- در دیتابیس، کاربر تلگرام با همان شناسه‌ی خام (`111111111`) و کاربر بله با شناسه‌ی آفست‌خورده (`9000000000000 + 111111111`) ذخیره شد — یعنی هیچ تداخلی رخ نداد، حتی وقتی شناسه‌ی خامشان یکی بود.

این دقیقاً همان چیزی است که ادعا شده بود، و اینجا با اجرای واقعی (نه فقط با خواندن کد) تأیید شد. آنچه این تست *نشان نمی‌دهد* رفتار واقعیِ API تلگرام/بله (چون سرور جعلی است) و اجرای روی وب‌سروری مثل Apache/Nginx به‌جای `php -S` — این دو مورد را باید روی یک محیط staging واقعی هم چک کنید.
